# NICE - NEW TASK: You are an expert wiki / kb documentation creator: Suggest how to parse to following information into two separate products -- one that is an \$1800 loss-leader single-page first website, the other is the same thing but it free in exchange for a testimonial (limit 2 per quarter on the loss-leader sites and 2 per year on the free ones)?

You can treat these as two tightly related “sibling” products in your wiki, each with its own page plus a shared parent concept.

## Top-level product family

Create a parent page like:

- `Single-Page Website Starter (Product Family)`
    - Defines the shared core:
        - Single-page brochure site
        - Same tech stack, SOP, scope, and time cap
        - Same visual layout and sections
    - Links to:
        - `$1,800 Starter Site` (loss-leader)
        - `Complimentary Starter Site` (testimonial)


## Product 1: \$1,800 loss-leader

Create a dedicated product page, for example:

- `Product: Single-Page Website Starter — $1,800`

Structure:

- Purpose
    - Paid, intentionally underpriced “entry” offer
    - Target: first-time website owners
- Offer details
    - Price: \$1,800
    - Inclusions: scope, sections, tech, time cap
    - Exclusions: copywriting, multi-page, etc.
- Capacity \& limits
    - “Max 2 projects per quarter”
    - How you track the quota
- Internal rules
    - When to say yes / no
    - Upgrade paths to bigger projects


## Product 2: Free in exchange for testimonial

Create a parallel page:

- `Product: Single-Page Website Starter — Complimentary/Testimonial`

Structure:

- Purpose
    - Free version used for proof, portfolio, and market learning
    - Clearly labeled as testimonial-exchange, not “pro bono”
- Offer details
    - Price: \$0 build, hosting still paid
    - Same core scope as \$1,800 product
    - Extra condition: written testimonial (and rights to use it)
- Capacity \& limits
    - “Max 2 projects per year”
    - Extra selectivity / red-flag criteria
- Internal rules
    - How you vet candidates
    - How you handle boundaries so it doesn’t sprawl


## What’s shared vs. duplicated

In the wiki:

- Shared (link to common docs)
    - Theme blueprint
    - SOPs (build process, time caps, scope guardrails)
    - Internal pricing rationale
- Differentiated (per-product page)
    - Pricing and quotas
    - Eligibility criteria
    - Intake questions
    - Contract / agreement templates (paid vs complimentary)

This gives you two clearly documented SKUs that reuse the same engine while making pricing, quotas, and expectations unmistakable.
